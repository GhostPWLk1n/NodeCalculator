# NodeCalculate v1.6.3

Патч-релиз: три исправления, всплывшие при плотной работе с Досками
(дашбордами) — от осиротевших виджетов до двойного скролла в диаграмме
Ганта. Без новой функциональности и без изменений формата `.ncp` —
обновление безопасно для существующих проектов.

## 🐛 Исправления

### Доска не убирала виджет удалённой ноды
Если ноду «Дашборд» удаляли из графа, её виджет оставался на Доске
навсегда — застывший, с последним посчитанным значением. Причина:
виджет регистрируется на Доске изнутри `calculate()` самой ноды, а
удалённая нода больше никогда не пересчитывается — снять виджет было
некому. Теперь удаление любой ноды явно снимает её виджет (если он был)
со всех Досок.

### Тормоза при редактировании виджетов на Доске с несколькими виджетами
Пересчёт графа выполняет несколько проходов подряд (чтобы значения
корректно распространились по цепочке), и каждый проход каждого
виджета-Дашборда безусловно перерисовывал всю страницу Доски. При 4
виджетах на доске одно нажатие клавиши в поле ввода могло вызывать
десятки лишних пересборок DOM — тот же главный поток, что обслуживает и
Лист с графом нод, отсюда ощутимые лаги при вводе. Перерисовка Доски
теперь откладывается и происходит максимум один раз за пересчёт,
независимо от числа виджетов.

### Ввод в 2-й, 3-й, 4-й виджет на Доске сбоил (в отличие от первого)
После предыдущего фикса вскрылся отдельный, более старый баг в
алгоритме обновления DOM Доски: сверка «что должно быть на экране» с
живым списком дочерних элементов страницы велась по индексу в
коллекции, которая сама менялась по ходу того же цикла. Из-за этого
поле ввода, в которое печатает пользователь, могло быть без нужды
физически перемещено в DOM прямо во время набора текста — что сбивает
позицию курсора в большинстве браузерных движков. Виджет на первой
позиции не задевало (перед ним в цикле ничего не переставлялось) — этим
и объяснялась разница в поведении. Алгоритм переписан на точную сверку
по ссылкам на элементы.

### Двойной скролл в диаграмме Ганта
Тело диаграммы (`.gantt-rows-scroll`) задавало только вертикальный
скролл, не указывая горизонтальный явно — спецификация CSS в этом
случае обязывает браузer молча включить и горизонтальный тоже. Как
только содержимое (длинные названия задач, линии сетки, подложка
выходных) хоть немного выходило за расчётную ширину, диаграмма
заводила собственную, вторую горизонтальную полосу прокрутки поверх
уже имеющейся внешней. Тот же класс бага, что ранее чинили в узле
«Просмотр таблицы» (v1.5.0) — исправлен тем же приёмом: горизонтальный
скролл теперь однозначно закреплён только за внешней обёрткой.

## 🔄 Совместимость

Изменения затрагивают только `nodeManager.js`, `boardManager.js` и
`ganttNode.js` (внутренняя логика рендера, без изменений формата
данных). Проекты `.ncp`, созданные в 1.5.0/1.6.0, открываются и
сохраняются без каких-либо преобразований.
