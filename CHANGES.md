# Правки после v1.2.0 (Table / TableViewer / String)

## Версия

`package.json` обновлён с `1.3.0` до **`1.4.0`** (minor - новая
функциональность, без поломки обратной совместимости). `v1.3.0` был
опубликован на GitHub как первая собранная под Windows сборка
("first build") — всё, что описано ниже как "Раунд 14" и далее
(удаление конкретной связи вместо очистки всех, замена связи на занятом
сокете, боковая панель настроек ноды, редизайн Table/TableViewer/
ListInput/Percentage, минимальная ширина 200px для всех нод, нода
"Диаграмма Ганта"), сделано ПОСЛЕ этой публикации и составляет разницу
между `v1.3.0` и `v1.4.0`. `@version` во всех файлах синхронизирован с
`package.json` (`1.4.0`) — при каждом следующем релизе обновляется
единым проходом по всем файлам (см. `docs/NODE_API.md`, раздел 2.1).

Ниже — все доработки и багфиксы поверх первоначального внедрения типов
String/Data и нод Table/PercentageNode (раздел "Новые возможности v1.2.0"
ниже), в порядке раундов правок.

## Раунд 1 — вид StringNode, переполнение Table, новая нода TableViewer
- `stringNode.js` переписан по образцу `numberNode.js`: компактная
  однострочная нода (`nodeManager.js` навешивает класс
  `string-node-compact`, CSS-блок в `styles.css` зеркалит
  `.number-node-compact`), категория в сайдбаре — "Ввод", не "Служебная".
- `tableNode.js`: контейнеры строк столбца (`table-column-row`,
  `table-column-line`) не имели `display:flex` ни в CSS, ни инлайн —
  сокет-`<div>` (блочный по умолчанию) переносился на свою строку и ломал
  раскладку. Добавлены явные inline flex-стили на все ряды.
- Новая нода `tableViewerNode.js`: вход Data, выходов нет, тип Viewer.
  Рендерит `<table>` с заголовками колонок и значениями через
  `Helpers.formatByType()`; заголовок ноды подхватывает имя источника.
- Зарегистрирована в `main.js`, добавлен пункт в `index.html`.

## Раунд 2 — цвет сокета String при подключении, реальная причина переполнения Table
- `renderer.js`/`styles.css`: CSS-правило "серой заливки по умолчанию"
  (`.socket.socket-connected.output/input-socket:not(.socket-list)…`) не
  исключало `.socket-string`/`.socket-data`, а за счёт более длинной
  цепочки `:not()` имело более высокую специфичность, чем цветные правила
  — побеждало вопреки порядку в файле. Добавлены исключения
  `:not(.socket-string):not(.socket-data)`.
- Настоящая причина переполнения `TableNode` по ширине: `content.style.
  minWidth` был жёстко привязан к ВНЕШНЕЙ ширине ноды (`this.width`), а не
  к реально доступному месту внутри паддингов (`box-sizing:border-box`).
  Заменено на `width:100%` с независимым минимумом — как в
  `percentageNode.js`. Тот же баг был и в `TableViewerNode` — исправлен.
- `tableViewerNode.js` перенесён из раздела "Таблицы" в "Визуализация";
  добавлен вертикальный скролл с "прилипающим" заголовком; для колонок
  формата `percent` в ячейке появилась линейная заливка-графа под текстом.

## Раунд 3 — фильтрация неподключённых столбцов, адаптивная высота Viewer
- `tableNode.js` `calculate()`: столбцы без подключённого LIST-источника
  ("заготовки" для следующего соединения) больше не попадают в
  `tableData` — иначе Viewer и `PercentageNode` показывали пустой столбец.
- `tableViewerNode.js`: высота области прокрутки считается по фактическому
  числу строк (до 8 строк без скролла, дальше скролл) вместо фиксированных
  260px; добавлены номера строк и кнопка-глазик, скрывающая их.
- `tableNode.js`: убран `padding-left:22px` у второй строки столбца — он
  сдвигал String-сокет от края, из-за чего тот не был вровень с
  LIST-сокетом сверху; дефолтная ширина ноды уменьшена 320→300px.

## Раунд 4 — лимит столбцов, свободный ресайз Viewer, названия строк
- `tableNode.js`: `maxColumns` поднят с 6 до 24 (было захардкожено).

- `tableNode.js`: чекбокс "имена" у каждого столбца — если включён и у
  источника есть `item.name`, перед числовым столбцом добавляется

- `tableViewerNode.js`: столбец номеров и кнопка-глазик раньше пропадали

- `tableNode.js`: у каждого столбца добавлено поле ручной ширины (px,
  пусто = авто), прокидывается через `TableData` в `TableViewerNode`.

## Раунд 5 — фиксированная ширина номеров, сортировка, редизайн строки столбца
- `tableViewerNode.js`: столбец номеров строк — фиксированной ширины,
  подбирается под количество цифр в `rowCount` (как в Excel), одинаковой
  у шапки и у всех ячеек.
- `tableViewerNode.js`: клик по заголовку столбца сортирует строки
  (по возрастанию → по убыванию → как есть, три состояния по кругу,
  иконка `↕`/`↑`/`↓`) — чисто визуально, исходные данные в `TableNode`
  не меняются; индекс сортировки сбрасывается, если набор столбцов
  источника изменился.
- `tableNode.js`: раскладка строки столбца пересобрана в
  `[String-сокет][имена][формат][ширина]` одной строкой (было раскидано
  по двум строкам с лишним лейблом "Столбец N"); `select` формата убрал
  `flex:1` (был избыточно растянут) — теперь компактные 56px; чекбокс
  "имена" получил `accent-color` под тёмную тему вместо белого нативного
  вида.

## Раунд 6 — Table/TableViewer не сворачивались, позиция ручки resize
- Настоящая причина: `TableNode`/`TableViewerNode` (и эталонный
  `exampleNode.js`) задавали `display:flex` ИНЛАЙН на `.node-content`, а
  инлайн-стиль без `!important` всегда побеждает CSS-класс — правило
  `.node.collapsed .node-content{display:none}` не срабатывало, контент
  никогда не скрывался. Фикс на двух уровнях: добавлен `!important` в
  само правило сворачивания (защищает вообще любую будущую ноду), плюс
  убран избыточный inline `display`/`flex-direction` из всех трёх файлов.
- `styles.css`: ручка изменения ширины ноды (`.node-resize-handle`) была
  `right:2px; bottom:2px` (внутри границ, перекрывала угол содержимого).
  Заменено на `right:-1px; bottom:-1px` — внешний край ручки теперь ровно
  на 1px выступает за пределы ноды по обеим осям.

## Раунд 7 — баг сохранения/загрузки .ncp после обновления схемы нод
- `layoutManager.js` `loadFromData()`: убрана строка
  `if (sn.inputs) node.inputs = sn.inputs;`. Она насильно перезаписывала
  уже корректно вычисленное конструктором `node.inputs` СОХРАНЁННЫМ (и
  потенциально устаревшим) числом. Пока у каждой ноды число входов было
  константой, это было безобидным no-op — но `PercentageNode` в этой
  сессии получил второй вход (1→2), а `TableNode`/`OperationNode` сами
  вычисляют `inputs` из `inputSockets.length`/`config` в конструкторе.
  Загрузка `.ncp`, сохранённого ДО этих изменений схемы (например, старый
  файл с `percentage`-нодой и `inputs:1`), откатывала `node.inputs`
  обратно на 1, рассинхронизируя его с `inputSockets` (длина 2).
  Конструктор каждой ноды и так корректно выставляет `inputs` из
  `config` — отдельная перезапись была лишней и в данном случае вредной.

## Раунд 8 — новая нода: Проценты от суммы (percentConvertNode.js)
- Обработчик LIST → LIST: каждый элемент входного списка заменяется на
  его долю (%) от суммы всех элементов, имена сохраняются
  (переиспользует готовый геттер `ListData.percentages`).
- Не путать с `PercentageNode` (рисует диаграмму) - этот узел только
  преобразует данные, результат можно подключить куда угодно, например,
  в столбец `TableNode`.
- Переопределяет `getValueFormat()` → `'percent'` (хук из `baseNode.js`,
  раздел "Новые возможности v1.2.0") - потребители с форматом "Авто"
  (например, столбец `TableNode`) сами подхватывают, что на выходе
  проценты, без ручной настройки. Каждый элемент выходного списка также
  несёт `format:'percent'`.
- Добавлена в раздел сайдбара "🔧 Преобразование", тип `percentConvert`,
  запись в `Constants.TYPE_NAMES`.

## Раунд 9 — итоги, decimals, группировка тысяч, фикс наложения sticky-заголовка
- `tableNode.js`: у каждого столбца новое поле `totalType`
  (`null`/`sum`/`max`/`min`/`avg`) - select "Сум/Бол/Мин/Сред" сразу после
  формата; и `decimals` (0-10, `null` = авто) - вынесено в отдельную
  строку 3 вместе с шириной, чтобы не перегружать строку 2. Оба поля
  прокидываются через `TableData` (сериализуются автоматически - они
  часть объекта `column`, отдельных правок в `layoutManager.js` не
  потребовалось).
- `dataTypes.js`: `TableData.aggregate(col)` - вычисляет итог по столбцу
  (сумма/наибольшее/наименьшее/среднее), нечисловые значения игнорирует,
  `null` без `totalType` или без чисел.
- `tableViewerNode.js`: строка "Итого" (`<tfoot>`) рендерится, только если
  хотя бы у одного столбца задан `totalType`; для остальных столбцов без
  итога ячейка пустая. Прилипает к низу обёртки при скролле (`position:
  sticky; bottom:0`), как заголовок прилипает к верху.
- `helpers.js`: `formatByType()` пробрасывает `decimals` в новую
  `formatGrouped(value, decimals)` - число со **пробелами**-разделителями
  тысяч (`1000` → `"1 000"`) и заданным числом знаков после запятой;
  `formatNumber()` (используется в редактируемых полях ввода) не тронут -
  группировка там была бы не к месту.
- **Фикс "таблица налезает на заголовки":** `border-collapse: collapse`
  в связке с `position: sticky` на ячейках - известный баг рендеринга
  Chromium (визуальные артефакты/наложение при скролле прилипающих
  ячеек). Заменено на `border-collapse: separate; border-spacing: 0`.

## Раунд 10 — точная высота скролла TableViewer, стиль resize-хэндла, компактный TableNode
- `tableViewerNode.js`: `applyWrapHeight()` считал высоту окна прокрутки
  по приблизительным константам (`HEADER_HEIGHT`/`ROW_HEIGHT`) и
  вызывался ДО того, как таблица вообще появлялась в DOM - то есть не
  знал ни настоящих размеров шапки/строки, ни того, будет ли строка
  "Итого" (`tfoot`). Из-за этого окно оказывалось то на строку заголовков
  ниже (константа не совпадала с реальной высотой шапки), то на строку
  итогов короче (`tfoot` вообще не учитывался). Теперь высота считается
  ПОСЛЕ вставки таблицы в `wrap`, по настоящим `offsetHeight` шапки,
  первой строки тела и `tfoot` (если есть) - никаких магических констант.
- `styles.css`: нативный resize-хэндл (`resize: both`) обёртки таблицы
  раньше рисовался браузером как диагональная иконка-уголок, выбивавшаяся
  из тёмной темы. Добавлено `.table-viewer-wrap::-webkit-resizer` -
  серая точка (`border-radius:50%`), согласованная по цвету/hover с
  `::-webkit-scrollbar-thumb`.
- `tableNode.js`: раскладка строки столбца сведена к двум строкам вместо
  трёх - `[LIST-сокет][имена][формат][итог][✕]` и
  `[String-сокет][px][зн:]`. Дефолтная ширина ноды уменьшена 340→300px.

## Раунд 11 — меньше точка resize, гарантированно непрозрачный фон sticky-ячеек
- `styles.css`: `.table-viewer-wrap::-webkit-resizer` переведён с
  `border-radius:50%` (заливает весь бокс резайзера, который у браузера
  крупнее, чем нужно визуально) на `radial-gradient` с явным радиусом
  5px - управляемый размер точки, независимый от фактического размера
  нативного бокса.
- `tableViewerNode.js`: все sticky-ячейки (шапка, номера строк, "Итого")
  переведены с сокращённого `background: var(--md-surface-variant)` на
  `background-color: var(--md-surface-variant)` + `will-change:
  transform` - гарантированно непрозрачный фон и отдельный композитный
  слой. Это известная особенность рендеринга `position: sticky` в
  Chromium: прокручиваемый контент иногда "просвечивает" сквозь
  sticky-ячейки даже при номинально непрозрачном цвете фона -
  `border-collapse: separate` (раунд 9) решал только часть симптома.

## Раунд 12 — архитектурный отказ от position:sticky в TableViewerNode
- `tableViewerNode.js` переписан: вместо одной `<table>` со sticky-шапкой
  и sticky-футером внутри общей прокручиваемой области - три физически
  раздельных блока в обычном потоке документа: `headerRow` (обычный
  поток), `bodyScroll` (собственный `overflow-y:auto`, только он и
  прокручивается вертикально), `footerRow` (обычный поток, ниже тела).
  Раунды 9-11 патчили СИМПТОМЫ известной особенности рендеринга Chromium
  у `position:sticky` (border-collapse, `background-color`+`will-change`)
  - этот раунд убирает саму причину, полностью отказавшись от sticky.
- Столбцы у всех трёх блоков выровнены не через `<table>`-раскладку и не
  через JS-синхронизацию скролла, а через явные одинаковые пиксельные
  ширины ячеек (`numColWidth` для номеров строк, `col.width` или
  эвристика по длине заголовка для остальных) - `getColumnWidths()`.
- Горизонтальный скролл - на внешней обёртке (`.table-viewer-wrap`,
  `overflow:auto`): `bodyScroll` не ограничивает свою ширину, поэтому её
  "вылезание" по горизонтали ловит внешняя обёртка, и шапка/тело/футер
  скроллятся синхронно одним нативным скроллом ("двойной overflow").
- Высота `bodyScroll` (`flex:1; min-height:0; max-height:<computed>`)
  считается ТОЛЬКО по строкам тела - шапка и футер физически вне этой
  области и в расчёт вообще не входят, что и убирает саму причину бага
  "на строку заголовков ниже / на строку итогов короче" на уровне
  архитектуры, а не приближённой оценки размеров.

## Раунд 14 — контекстное меню: "Очистить соединения" → "Удалить связь"
- Раньше пункт меню "🔗 Очистить соединения" был доступен только через
  правый клик по НОДЕ и стирал ВСЕ соединения проекта разом
  (`connectionManager.clearAll()`), без привязки к конкретной ноде или
  связи. Теперь правый клик по САМОЙ ЛИНИИ соединения открывает то же
  меню с единственным пунктом "🔗 Удалить связь", который удаляет именно
  эту связь (`connectionManager.removeConnection(...)`, уже
  существовавший метод, просто не был доступен из UI для одной связи).
- `renderer.js`: `createConnectionPath()` теперь строит ПАРУ элементов -
  невидимый широкий `hitArea` (`stroke-width:14`, `pointer-events:stroke`,
  ловит клик/наведение) и видимую тонкую линию `path`
  (`pointer-events:none`, чисто декоративная) - по родной 2.5px линии
  сложно попасть правой кнопкой мыши, hitArea даёт удобную область
  клика без изменения визуальной толщины линии. Наведение на hitArea
  подсвечивает связь (толще + непрозрачнее) - видно, что удалишь.
  `drawAllConnections()` при перерисовке удаляет старые hitArea вместе
  со старыми path (иначе накапливались бы при каждом пересчёте графа).
- `connectionManager.js`: новое поле `contextMenuTarget` (конкретное
  соединение, а не просто id ноды) и `showConnectionContextMenu(x, y,
  conn)` - показывает общее меню, скрывая пункты, относящиеся к нодам.
- `nodeManager.showContextMenu()`: наоборот, скрывает "Удалить связь" и
  сбрасывает `connectionManager.contextMenuTarget` - режимы "выбрана
  нода" и "выбрана связь" взаимоисключающие.
- `index.html`: всем пунктам меню присвоены `id` для программного
  переключения видимости; глобальный обработчик закрытия меню (клик
  вне его пределов) сбрасывает обе цели.

## Раунд 15 — занятый сокет: замена связи вместо отказа
- `connectionManager.js` `finishConnection()`: раньше перетаскивание
  новой связи на уже занятый вход отклонялось целиком ("⚠️ Вход уже
  занят"), и приходилось сперва вручную удалять старую связь. Теперь,
  если целевой сокет занят, старая связь автоматически удаляется
  (`removeConnection`) перед созданием новой (`addConnection`) - статус
  показывает "🔗 Связь заменена" вместо отказа. Проверка совместимости
  типов сокетов (list/string/data/plain) по-прежнему выполняется ДО
  замены - несовместимое соединение не трогает существующую связь.

## Раунд 16 — сборка под Windows: фикс "Cannot create symbolic link" (winCodeSign)
- `electron-builder` при СБОРКЕ ПОД WINDOWS всё равно пытается скачать
  `winCodeSign` (инструмент подписи для macOS) из-за автообнаружения
  сертификата подписи (`CSC_IDENTITY_AUTO_DISCOVERY`). Архив
  `winCodeSign-2.6.0.7z` содержит symlink'и на `.dylib`-файлы, а Windows
  без прав администратора/Developer Mode не даёт их создавать - сборка
  падала на распаковке этого архива, хотя для чисто Windows-инсталлятора
  он вообще не нужен.
- `package.json`: все `dist*`-скрипты теперь запускаются с
  `CSC_IDENTITY_AUTO_DISCOVERY=false` (через `cross-env`, новый
  devDependency - чтобы переменная окружения ставилась одинаково что в
  cmd, что в PowerShell, что в bash) - отключает автообнаружение
  сертификата и, соответственно, необходимость в `winCodeSign` для
  Windows-сборки.

## Раунд 17 — боковая панель настроек ноды (InspectorManager)
- Новый модуль `core/inspectorManager.js` - правая боковая панель,
  открывается когда нода в фокусе (клик по ноде), закрывается по клику
  на пустой холст, по Escape, при удалении/пересоздании выбранной ноды
  или переключении листа. Задача - вынести тонкую настройку из самой
  ноды наружу, чтобы нода оставалась компактной.
- Панель ничего не знает о конкретных типах нод - рендерит схему полей,
  которую возвращает `node.getInspectorSchema()`. Любая нода может
  добавить свои поля, вызвав `super.getInspectorSchema()` и дописав к
  результату (типы поля: `text`/`color`/`select`/`number`/`checkbox`).
- `baseNode.js`: базовая схема (доступна ЛЮБОЙ ноде без переопределения)
  - поле "Имя" (дублирует переименование двойным кликом по заголовку,
    но доступно и из панели) и новое поле "Цвет узла" - акцентная
    полоска слева (`box-shadow: inset`, не влияет на layout), сбрасывается
    отдельной кнопкой "↺" к цвету темы по умолчанию.
- `numberNode.js`: дополняет базовую схему полем "Формат значения"
  (Число/Деньги/Проценты) - та самая отложенная "тонкая настройка",
  которую в самом начале решили не встраивать в тело ноды, а вынести в
  будущую боковую панель (см. `BaseNode.getValueFormat()`, раздел
  "Новые возможности v1.2.0" ниже). Другие ноды могут добавить это поле
  себе по тому же образцу.
- `nodeManager.js`: `selectNode()`/`deselectNode()` (класс
  `inspector-selected` + вызов `inspectorManager.open()/close()`) и
  `applyNodeColor()` (применяет `--node-accent` + класс
  `has-custom-color`, вызывается и при первом рендере, и при каждом
  изменении из панели).
- `color`/`valueFormat` сериализуются в `.ncp` как обычные поля ноды
  (`valueFormat` уже был в списке, `color` добавлен).

## Раунд 20 — TableViewerNode: один ресайз-хэндл вместо двух + новая нода "Диаграмма Ганта"
- **Убран дублирующий хэндл ресайза.** У `TableViewerNode` раньше было
  два независимых способа менять размер: общая ручка ноды (только
  ширина) и нативный `resize:both` на `.table-viewer-wrap` (ширина+
  высота) - по сути одно и то же в разных углах. Теперь ресайз только
  через общую ручку ноды, но для неё сделано исключение: если нода
  реализует `beginFreeResize(el)`/`applyFreeResize(el, deltaY)`, та же
  самая ручка тянет и высоту тоже, в обход общего правила "высота только
  по контенту" (`nodeManager.js`) - осознанное исключение, а не
  нарушение. Курсор ручки становится диагональным
  (`.node-resize-handle.free-resize`) для таких нод.
  `TableViewerNode.applyFreeResize()` передаёт дополнительную высоту в
  `.table-viewer-wrap` (`wrapHeight`, сериализуется в `.ncp`) - строк
  показывается больше/меньше без пересоздания DOM.
- **Новая нода: `ganttNode.js` - "Диаграмма Ганта"** (раздел сайдбара
  "Преобразование", тип `gantt`). Вход 0 - LIST задач (имя = задача,
  значение = длительность в часах или днях, единица - в панели). Задачи
  по умолчанию ставятся последовательно друг за другом от даты начала
  плана; полосу любой задачи можно перетащить мышью по горизонтали -
  новое начало запоминается по имени задачи (`this.taskDates`) и
  переживает пересчёт графа и сохранение проекта. Вход 1 - альтернативная
  готовая таблица (Data): если её заголовки содержат "начало"/"окончание"
  (`isCompatibleTable()`), нода использует её НАПРЯМУЮ для отрисовки,
  без пересчёта из списка - так на вход можно подать её же собственный
  выход, отредактированный в другом узле. Выход - Data-таблица
  (Задача/Начало/Окончание/Длительность). Боковая панель (раздел
  "Календарь"): дата начала плана (`type: 'date'` - новый тип поля в
  `InspectorManager`), период отображения (Месяц/Квартал/Полгода/Год),
  единица длительности (Часы/Дни). Дат-хелперы (`addDays`/`formatDateRu`/
  `parseDateRu`/`daysBetween`) - без внешних библиотек, чистый `Date`.

## Раунд 21 — Диаграмма Ганта: масштаб линейки, сетка, зебра, дедлайн
- `ganttNode.js`: фиксированный `DAY_WIDTH` заменён на `RULER_SCALES`
  (Часы/Дни/Недели) - каждый пресет задаёт и плотность (px на день:
  48/22/10), и шаг делений линейки (1 день у "часов"/"дней", 7 дней у
  "недель"). Данные по-прежнему считаются в днях - режим "Часы" не
  хранит время суток отдельно, а просто даёт более широкий масштаб для
  точной расстановки коротких задач. `dayWidth` теперь параметр, а не
  константа - прокидывается через `buildRuler`/`buildTaskRow`/
  `attachBarDrag`, чтобы перетаскивание полосы корректно работало на
  любом масштабе (использует АКТУАЛЬНЫЙ `dayWidth` на момент драга).
- Вертикальные линии-разделители дат через все строки задач сразу
  (`showGridLines`, чекбокс в панели) - `buildGridLines()`, тот же шаг,
  что у делений линейки, отрисовывается в `position:relative`-обёртке
  строк, чтобы линии растягивались на полную высоту всех задач (не
  только видимую при скролле часть).
- Зебра для строк задач (чётные - `rgba(255,255,255,0.02)`, тот же
  паттерн, что и в `tableViewerNode.js`).
- Дедлайн плана (`deadlineDate`, поле типа `date` в панели) - красная
  вертикальная линия (`buildDeadlineLine()`) поверх линейки и строк,
  позиция считается как смещение дедлайна от даты начала плана в днях.
- `layoutManager.js`: `rulerScale`/`showGridLines`/`deadlineDate`
  добавлены в сериализацию `.ncp` для типа `gantt`.

## Раунд 22 — Гантт: многоуровневая шапка, ручка дедлайна, подложка выходных
- **Треугольная ручка дедлайна.** Отдельная узкая строка над шапкой
  (`buildDeadlineHandle()`, обычный поток, не абсолютный элемент с
  отрицательным `top` - иначе обрезалась бы `overflow-y:hidden` внешней
  прокрутки). Перетаскивание (`attachDeadlineDrag()`) меняет
  `this.deadlineDate` - тот же паттерн document-level
  mousemove/mouseup, что и у полос задач, плюс обновление боковой
  панели, если она открыта для этой ноды. Дедлайн разрешено утащить
  раньше даты начала плана - осмысленное состояние ("план уже сорван"),
  не ошибка.
- **Многоуровневая шапка для масштаба "Дни".** Раньше линейка была одной
  строкой независимо от масштаба; теперь при `rulerScale === 'days'`
  вместо неё - четыре независимо переключаемые строки сверху вниз: год /
  месяц / число / день недели (`buildDaysHeader()`). Год и месяц -
  сгруппированные сегменты (`buildGroupedRow()` - соседние дни с
  одинаковым годом/месяцем схлопываются в один подписанный блок, не
  дублируют подпись на каждый день); число - календарный день месяца на
  каждую ячейку; день недели - `пн/вт/.../вс`, выходные выделены
  красноватым текстом и жирным начертанием. Для других масштабов
  (Часы/Недели) поведение не изменилось - там по-прежнему одна строка
  линейки (`buildRuler()`).
- Столбцы выходных (сб/вс) дополнительно подсвечены на всю высоту
  диаграммы, не только в строке дня недели (`buildWeekendHighlights()`,
  тонкая подложка `rgba(239,83,80,0.06)`) - появляется только вместе со
  строкой "день недели" (`rulerScale==='days' && showWeekdayRow`), это
  одна связанная фича, а не два независимых переключателя.
- Боковая панель: 4 новых чекбокса ("Показывать год/месяц/число/день
  недели") - видны в схеме, только когда `rulerScale === 'days'` (в
  других масштабах у шапки одна строка, переключать нечего).
- `layoutManager.js`: `showYearRow`/`showMonthRow`/`showDayRow`/
  `showWeekdayRow` добавлены в сериализацию `.ncp` для типа `gantt`.

- `socketFactory.js`: добавлены опции `isString`/`isData`; каждый сокет

  предположения "это всегда просто число".

## Нода String (`stringNode.js`)
- Компактная служебная нода: одно текстовое поле, один выход типа String.
- Предназначена для заголовков/подписей — например, заголовков колонок
  таблицы.

## Нода Table (`tableNode.js`)
- Обработчик: собирает несколько LIST-входов в столбцы таблицы.
- У каждого столбца два входа — LIST (обязательный) и String
  (необязательный, переопределяет заголовок столбца) — с уникальными
  индексами сокетов на столбец (см. docs/NODE_API.md, раздел 5).
- Автодобавление нового пустого столбца по заполнении последнего
  (паттерн `checkAndAddEmptySlot`/`rerender` из `operationNode.js`).
- У колонки можно вручную выбрать формат (Авто/Число/Деньги/Проценты);
  при "Авто" формат наследуется от `getValueFormat()` источника-списка.
- Выход — сокет типа Data с готовой `TableData`.
- Сериализация: `columns`/`_nextIndex` добавлены в `layoutManager.serialize()`.

## percentageNode — второй вход Data
- Добавлен второй, альтернативный вход (Data, index 1) — если подключены
  оба входа одновременно, побеждает Data (у него уже есть явные заголовки
  колонок из String).
- Легенда диаграммы показывает значение с учётом формата колонки

- Переименование: `prompt()` заменён на инлайн-редактирование во вкладке
  (window.prompt в Electron не поддерживается). Переименование — двойной
  клик по АКТИВНОЙ вкладке (Enter — сохранить, Escape — отмена).
